# ربات رزرو تور در تلگرام

[English](README.md) · مجوز GPL-3.0-only

ربات متن‌باز و قابل میزبانی مستقل با رابط فارسی، برای معرفی تور، رزرو گروهی،
بررسی مدیر، تأیید دستی پرداخت و اعلان‌های پایدار. عمومی بودن مخزن به معنی
وجود یک ربات میزبانی‌شده نیست؛ هر اپراتور توکن، دیتابیس و دامنه خودش را لازم دارد.

این محصول برای برگزارکننده‌ای است که می‌خواهد رزرو تور را در ربات تلگرام خودش
مدیریت کند: مسافر تور را پیدا و صندلی رزرو می‌کند؛ مدیر ظرفیت، تأیید درخواست،
پرداخت دستی و اعلان‌ها را از همان رابط فارسی مدیریت می‌کند.

**از اینجا شروع کنید:** [نصب](#نصب-از-صفر) · [راهنمای مسافر](#استفاده-مسافر) ·
[مدیریت](#مدیریت) · [دامنه محصول و محدودیت‌ها](docs/PRODUCT.md) · [ارتقا و بازیابی](docs/DEPLOYMENT.md).
نسخه تحویلی سورس در شاخه `master` است؛ سرویس اشتراکی یا میزبانی عمومی ارائه نمی‌شود.

**انتشار کد متن‌باز به معنی تأیید محیط Production نیست.** آزمون‌های خودکار با داده ساختگی،
Telegram شبیه‌سازی‌شده و پرداخت شبیه‌سازی‌شده محلی اجرا می‌شوند. اتصال زنده
تلگرام، VPS و درگاه پذیرندگی جداگانه باید بررسی شوند.

## نصب از صفر

Git، Docker Engine و Compose را نصب کنید:

```bash
git clone https://github.com/AlirezaBelal/travel-tour-reservation-bot.git
cd travel-tour-reservation-bot
cp .env.example .env
```

در `.env` توکن ربات، شناسه عددی مدیر اصلی، دو گذرواژه متفاوت دیتابیس و root و
`PROFILE_ENCRYPTION_KEY` تصادفی ۳۲ بایتی با رمزگذاری base64 را تنظیم کنید؛ با دستور `php -r 'echo base64_encode(random_bytes(32)), PHP_EOL;'` آن را تولید کنید. کلید باید در Secret Store و نسخه پشتیبان امن جداگانه بماند. از دست‌دادن آن به معنای غیرقابل‌بازیابی شدن شماره و کد ملی ذخیره‌شده است.
در نصب جدید پس از موافقت اپراتور با جمع‌آوری اطلاعات، برای الزامی‌کردن احراز اولیه پروفایل `REQUIRE_VERIFIED_PROFILE=true` بگذارید. برای Secret وبهوک از `openssl rand -hex 32` استفاده
کنید. فایل تکمیل‌شده را هرگز Commit نکنید.

```bash
docker compose build app
docker compose run --rm migrate php bin/install.php
docker compose run --rm migrate php bin/restrict-runtime.php --confirm
docker compose up -d
curl -f http://127.0.0.1:8080/health.php
```

سرویس `worker` باید فعال باشد؛ تمام پیام‌ها ابتدا وارد صف دیتابیس می‌شوند.
HTTP فقط روی `127.0.0.1:8080` باز است. با Reverse Proxy و گواهی معتبر، HTTPS
دامنه خود را به این پورت متصل کنید. فقط پوشه `public/` باید در دسترس وب باشد.

در **@BotFather** دستور `/newbot` بدهید، نام و Username انتخاب کنید و توکن را
خصوصی نگه دارید. وبهوک `https://YOUR_DOMAIN/index.php` را با `setWebhook` ثبت
کنید؛ `secret_token` باید با `TELEGRAM_WEBHOOK_SECRET` برابر و `allowed_updates`
شامل `message` و `callback_query` باشد. توکن و Secret را در Issue، عکس یا
لاگ عمومی نگذارید. پس از آماده‌بودن دامنه و HTTPS، از ابزار آماده استفاده کنید:

```bash
docker compose run --rm app php bin/set-webhook.php https://YOUR_DOMAIN/index.php --check
docker compose run --rm app php bin/set-webhook.php https://YOUR_DOMAIN/index.php --confirm
```

دستور اول فقط قالب تنظیمات را بررسی می‌کند. دستور دوم به تلگرام متصل می‌شود؛
فقط برای ربات و دامنه مجاز خودتان اجرا کنید. Secret چاپ نمی‌شود و Updateهای
منتظر حذف نمی‌شوند. سپس در گفتگوی خصوصی با ربات، `/start` را بفرستید.

برای دیتابیس موجود، ابتدا [راهنمای ارتقا](docs/MIGRATION.md) را بخوانید.
دستور `docker compose down -v` داده‌های Volume را حذف می‌کند؛ روی داده واقعی
از آن استفاده نکنید. [راهنمای عملیات](docs/DEPLOYMENT.md).

داده نمونه اختیاری: فقط در محیط دورریختنی، `APP_ENV=development` بگذارید و
`docker compose run --rm app php bin/seed-demo.php --confirm` را اجرا کنید.
تور نمایشی پیش‌نویس می‌ماند و اجرای تکراری داده تکراری ایجاد نمی‌کند.

## استفاده مسافر

۱. `/start` و «پروفایل»؛ نام سرپرست، شماره تماس از طریق دکمه رسمی اشتراک مخاطب تلگرام (فقط شماره صاحب حساب)، و کد ملی ۱۰ رقمی با رقم کنترل معتبر ثبت می‌شوند.
۲. تورها را از فهرست، دسته‌بندی یا جست‌وجوی عنوان و مقصد پیدا کنید.
۳. تاریخ، مقصد، قیمت و ظرفیت را ببینید؛ تعداد نفرات ۱ تا ۲۰ را وارد و درخواست را تأیید کنید.
۴. وضعیت و تاریخچه در «رزروهای من» دیده می‌شود؛ لغو نیز از همین بخش است.
۵. برای هماهنگی پرداخت دستی، «پیام به مدیریت درباره رزرو» را بزنید؛ مدیر با
«پیام به سرپرست» از داخل همین ربات پاسخ می‌دهد. شماره کارت، رمز یا کد ملی نفرستید.

قیمت‌ها **ریال** هستند، نه تومان. تاریخ ورودی میلادی و ساعت نمایش پیش‌فرض
تهران است؛ ذخیره‌سازی UTC است. رزرو منتظر بررسی، ظرفیت را نگه می‌دارد.
درخواست پولی بدون پرداخت تأییدشده پس از ۲۴ ساعت توسط Worker رد و ظرفیتش
آزاد می‌شود. لغو توسط مسافر تا پیش از شروع تور ممکن است. ثبت مجدد همان تور
پس از لغو در مسیر خودکار فعلی پشتیبانی نمی‌شود.

`/cancel` فرم جاری را متوقف می‌کند؛ `/help` راهنمای داخلی است.
جنسیت و تاریخ تولد در ثبت‌نام جدید دریافت نمی‌شوند. عضویت در دسته‌ها برای رزرو الزامی نیست.
شماره و کد ملی در جدول مجزای `TravelerIdentity` رمزگذاری می‌شوند و در CSV، منوی مدیر و لاگ ظاهر نمی‌شوند. کد ملی صرفاً از نظر رقم کنترل بررسی می‌شود؛ استعلام هویت از ثبت احوال انجام نمی‌گیرد.
میزبان با `REQUIRE_VERIFIED_PROFILE=true` تکمیل مشخصات را پیش از رزرو الزامی می‌کند؛ پیش‌فرض برای حفظ سازگاری ارتقا `false` است.
مسیر قدیمی `/setprofile` و عضویت دسته‌ها برای سازگاری حفظ شده‌اند.

## مدیریت

شناسه عددی مدیر اصلی در `TELEGRAM_ADMIN_IDS` است. با `/admin` وارد شوید:

- دسته و تور پیش‌نویس ایجاد کنید؛ مقصد، توضیح، تاریخ، قیمت و ظرفیت را با فرم فارسی وارد کنید.
- برای نمایش عمومی، تور را منتشر کنید؛ ویرایش، غیرفعال‌سازی و بایگانی در جزئیات تور هستند.
- درخواست منتظر را تأیید یا با دلیل اختیاری رد کنید.
- برای تور پولی، ابتدا واریز را واقعاً بررسی و شناسه یکتای اپراتور را ثبت کنید، سپس رزرو را تأیید کنید.
- گزارش ظرفیت، خروجی CSV، ارسال به مسافران یک تور یا همه کاربران و خطاهای صف را بررسی کنید.
- تغییر نقش‌ها، حذف دسته، بایگانی تور و حذف حساب تأیید دارند.

نقش «مدیر» تور، پرداخت، رزرو، صف و گزارش را مدیریت می‌کند؛ «بررسی» فقط رزرو
و آمار را می‌بیند؛ «گزارش» فقط آمار. فقط مدیر اصلی نقش تعیین می‌کند. مشاهده
نام سرپرست محدود و ثبت‌شده در Audit Log است. CSV نام، موبایل، کد ملی یا شناسه
تلگرام مسافر ندارد و سلول‌های خطرناک برای Excel خنثی می‌شوند.

## پرداخت و اعلان

پرداخت واقعی و استرداد خودکار فعال نیستند. وضعیت پرداخت از رزرو جداست.
لغو رزرو پرداخت‌شده ظرفیت را آزاد می‌کند، اما وجه باید با اپراتور تسویه شود.
`SandboxPaymentAdapter` یک **شبیه‌ساز امضاشده محلی** است، نه Sandbox یک
درگاه تجاری. امضا، مبلغ، سفارش، زمان و تکراری‌نبودن تراکنش بررسی می‌شوند.
درگاه واقعی بدون حساب پذیرنده، کلید و مستندات رسمی معتبر **BLOCKED EXTERNAL** است.
`PAYMENT_SANDBOX_ENABLED` را در استفاده عادی `false` نگه دارید؛ شبیه‌ساز در
`APP_ENV=production` حتی با این پرچم فعال هم اجرا نمی‌شود.

اعلان همراه تغییر رزرو در همان تراکنش ذخیره می‌شود. Worker، Retry نمایی،
محدودیت ارسال، خطای 429، یادآوری و ارسال ناموفق را مدیریت می‌کند. جلوگیری از
تکرار درج صف و تغییر وضعیت وجود دارد؛ ارسال تلگرام «حداقل یک‌بار» است و در
فاصله بین پذیرش پیام توسط تلگرام و ثبت نتیجه دیتابیس، تکرار احتمالی کاملاً
حذف‌شدنی نیست. ادعای تحویل دقیقاً یک‌بار وجود ندارد.

## حریم خصوصی و تست

از `/privacy` می‌توان حذف حساب خواست. ردیف رمزگذاری‌شده شماره و کد ملی با حذف حساب خودکار پاک می‌شود. ابتدا رزروهای فعال را لغو کنید. نام،
پروفایل قدیمی و مشخصات همراهان حذف و ارتباط حساب با سوابق بسته‌شده قطع
می‌شود؛ سوابق عددی بی‌نام برای گزارش باقی می‌مانند. پیام‌های قبلی تلگرام و
پشتیبان‌ها تابع سیاست جداگانه اپراتورند. پاک‌سازی خودکار پروفایل در حالت پیش‌فرض خاموش است تا داده موجود هنگام ارتقا
ناخواسته حذف نشود. اپراتور پس از تصویب و اعلام سیاست، `RETENTION_ENABLED=true`
و `RETENTION_DAYS` (پیشنهاد ۱۸۰ روز) را تنظیم می‌کند. درخواست صریح حذف حساب
مستقل از این گزینه فعال است. شمارنده امنیتی محدودیت پیام تا ۲۴ ساعت باقی می‌ماند تا حذف حساب، محدودیت ارسال را دور نزند.

`composer test:unit` و `composer test:integration` تست‌ها را اجرا می‌کنند.
تست دیتابیس فقط باید روی دیتابیس دورریختنی با نام دقیق `travel_tour_test` اجرا
شود. [معیارهای پذیرش](docs/ACCEPTANCE.md)، [معماری](docs/ARCHITECTURE.md)،
[مشارکت](CONTRIBUTING.md) و [امنیت](SECURITY.md) را ببینید.

اگر توکن واقعی در تاریخچه عمومی Git بوده است، از BotFather آن را عوض کنید؛
حذف فایل فعلی کافی نیست. هیچ Secret واقعی در نمونه‌ها یا تست‌ها قرار ندهید.
